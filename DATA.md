# Data and Model Assets

This repository contains experiment identities, not third-party pixels or pretrained weights.

## DINOv3 checkpoints

Obtain the official DINOv3 source and pretrained checkpoints through Meta's official access process. The paper uses the following identities:

| Scale | Constructor | Checkpoint filename | Expected bytes | Feature width |
|---|---|---|---:|---:|
| S | `vits16` | `dinov3_vits16_pretrain_lvd1689m-08c60483.pth` | 86,531,063 | 384 |
| B | `vitb16` | `dinov3_vitb16_pretrain_lvd1689m-73cec8be.pth` | 342,860,279 | 768 |
| L | `vitl16` | `dinov3_vitl16_pretrain_lvd1689m-8aa4cbdd.pth` | 1,213,050,671 | 1,024 |

Checkpoint files can be stored anywhere. Supply the path with `--checkpoint`.

## TAP-Vid-DAVIS

Obtain TAP-Vid-DAVIS through the official TAPNet repository instructions. The expected file is a trusted `tapvid_davis.pkl` mapping with 30 sequence records. Each record must contain:

```text
video:     uint8 [T, H, W, 3]
points:    floating point [N, T, 2], normalized (x, y)
occluded:  bool [N, T]
```

The loader converts normalized `(x, y)` coordinates to pixel coordinates using the frame width and height. Use only a dataset file obtained from a trusted source because the official format uses Python pickle.

The release contains the exact paper identities:

- 30 sequence folds;
- 23,686 unique source interfaces;
- 23,500 valid `+1` transitions;
- 20,886 valid `+4` transitions;
- 24,565 source/target interfaces;
- a fixed cross-scale support subset with 3,840 `+1` source anchors and 3,366 `+4`-eligible anchors;
- a fixed continuity subset with 960 `+1` and 890 `+4` transitions;
- saved donor identities for the fixed continuity comparisons.

These identities are stored under `assets/manifests/` and contain sequence, track, frame, coordinate, fold, transition, and deterministic source-view information. They do not contain video frames.

## Synthetic states

Synthetic images are generated by the included deterministic renderer. No external mesh, texture, or image is needed.

`assets/manifests/synthetic_conditions.csv` stores 32 independent object identities:

- 16 Existing16 identities;
- 16 New16 holdout identities.

Each identity has 14 one-factor-at-a-time source states:

- 5 configurations;
- 4 constraint-axis states;
- 3 joint locations;
- 2 motion families.

Each source state uses 8 common-visible material points and four future offsets: `-6`, `-3`, `+3`, and `+6`.

The manifest stores the exact object parameters, appearance parameters, material-point IDs, and identity indices needed to preserve deterministic rendering and source-observation seeds.

## Output storage

Feature extraction writes portable NumPy arrays and CSV metadata:

```text
<output>/
  metadata.csv
  store.toml
  center.npy
  states.npy
  future.npy                 # synthetic only
  rgb.npy                    # synthetic only
  projected_geometry.npy     # synthetic only
```

The arrays are memory-mappable and never require pickle. Generated feature stores can be large and are intentionally excluded from version control.
